# 0.3.0 — 2026-09-17

## Changed

- **`mcp-error-triage`** asks two questions, `origin` and `message_clarity`. `severity` is removed along with the `occurrences` state field it restated. `message_clarity` judges `error.shown_to_caller` — the input's `toolMessage`, else `message` — and sees the upstream detail only as `error.upstream_detail`. The input may carry `tools` when the same error was folded across tools. Derived fields are now `heuristic`, `origin_disagrees` (a committed disagreement at 0.6 confidence or more), and `opaque_message`; `agrees_with_heuristic` and `escalate` are gone. State text is capped at 600 characters.
- **`runExperiment`** throws at the first 401 or 403 instead of recording a failure for every record; `jev run` prints the provider's message once and exits 1.
- **`JevClient.ask`** retries a timeout or a dropped connection on the same backoff as a 429 or 5xx.

## Added

- **`JevHttpError`** (`status`, `isAuthFailure`), exported from the client module, thrown for any non-2xx answer after retries.
- **`docs/findings.md`**: what the rework measured — clarity had been judged on text the caller never saw, severity tracked the count, no question flags the largest patterns, and collapsing near-duplicates before sending halved the input.
- **`samples/mcp-errors.jsonl`**: a record with `toolMessage` and `tools`.
