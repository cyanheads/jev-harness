# Decisions

Append-only. One entry per decision: what, and the one- or two-sentence why.

- **2026-09-17 — Experiments are TypeScript files, not JSON or CLI flags.** The questions are data, but turning an input record into `state` is code (pick fields, drop the label, rename). A TS file with `defineExperiment` keeps both in one place with types; JSON would push the mapping back into hand-prepared data, and flags would make every run a chore.
- **2026-09-17 — Own client instead of `@typesafe-ai/sdk`.** The SDK targets `api.typesafe.ai/v1/systemone`; OpenRouter serves the same body at `/api/alpha/decisions` but validates `instructions`/criteria as strings. A ~150-line fetch client covers both providers, JSON-encodes structured entries for OpenRouter, and keeps the retry and cost accounting visible.
- **2026-09-17 — OpenRouter is the default provider.** TypeSafe's own API is waitlisted; OpenRouter lists `typesafe/jev-1.13` at the same price with no waitlist. `JEV_PROVIDER=typesafe` switches when a direct key exists.
- **2026-09-17 — Default model is the pinned `typesafe/jev-1.13`, not `jev-latest`.** Aliases move when a release ships and change answers under tuned thresholds. The response's `model` field is logged on every row.
- **2026-09-17 — Bun's native test runner, not Vitest.** No config, no dependency, and nothing here uses Vitest-only APIs. `bun test` and `bun run test` are equivalent in this repo.
- **2026-09-17 — Rows stream to JSONL as they complete; the report is computed after.** A long run that dies mid-way still leaves every finished row on disk. Input and state are excluded from rows by default (`--keep-input`, `--keep-state`) to keep result files small.
- **2026-09-17 — `derive` is where policy lives.** Thresholds, agreement with a carried label, and derived decisions are code in the experiment file, tallied in the report. Re-weighting is a code change, not a re-prompt.
- **2026-09-17 — LLM comparison mode is designed but not built.** See `docs/llm-comparison.md`.
- **2026-09-17 — Analysis lives in `src/analysis/`, behind `jev calibrate` and `jev stability`.** Two experiments needed the same reliability tables, which is the bar for moving code out of an experiment file. Both commands read rows from disk and never call Jev, so checking a threshold costs nothing.
- **2026-09-17 — Measured behavior is recorded in `docs/findings.md`, fleet-specific leads are not.** The findings file carries aggregate numbers about how Jev behaves. What a run surfaced about a particular server belongs with that server's issue tracker or the operator's own notes, never in this repo.
- **2026-09-17 — `mcp-error-triage` escalates on summed level probability, and dropped `dx_gap`.** On real error data the top Score level's confidence averaged 0.55, so a confidence gate passed 1% of rows; mass on the top two levels at 0.8 passed 15% and read as a usable queue. `dx_gap` exceeded 0.7 on 58% of input errors and separated nothing.
- **2026-09-17 — `mcp-error-triage` asks two questions and sees no counts.** `severity` restated the `occurrences` field it was sent, so both are gone; ranking by count is the consumer's job. `message_clarity` reads `shown_to_caller` (the tool's own error text) rather than the most detailed log message, which was often an upstream body the caller never saw. Origin disagreements below 0.6 confidence are dropped in `derive`, since those were the ones where Jev was wrong.
- **2026-09-17 — A run stops at the first 401 or 403; timeouts and dropped connections retry.** A rejected key fails every record the same way, and an unattended run should say so once and exit instead of logging a thousand failures. A timeout is as transient as a 503 and one lost record leaves a hole in a downstream queue.
- **2026-09-17 — Consumers call the CLI, not the library.** RemoteSysAdmin's `triage-mcp-errors.ts` spawns `jev run` and reads the rows file, joining on the record `id`. That keeps the questions and thresholds in the experiment file, lets the harness load its own `.env`, and needs no package link between the repos.
- **2026-09-18 — `mcp-error-triage` judges clarity on message plus recovery hint, and a `server` disagreement needs 0.75.** The framework shows a caller `Error: <message>` then `Recovery: <hint>`; judged on the message alone, 14 of 18 opaque patterns had in fact shown a usable hint. The per-direction threshold comes from a verified review: `upstream` and `input` disagreements at 0.6 and up produced the real findings, while every `server` call against `input` (0.60–0.74) was a malformed query from the caller.
- **2026-09-18 — An input whose record ids repeat is rejected.** `calibrate`, `stability`, and the downstream reader all join rows on `id`, and a repeat silently overwrote one row with another in each of them. Failing at load costs nothing; a wrong join is invisible.
- **2026-09-18 — An `onRow` that throws ends the run.** The sink failing (a full disk) is not a fact about the record, and filing it as a per-record failure put the record in both `rows` and `failures`.
- **2026-09-18 — `retry-after` is honored up to a minute; 408 and 504 retry.** An uncapped header let one response park a worker for as long as it named, with nothing printed. A gateway timeout is as transient as the 524 that already retried.
- **2026-09-18 — `calibrate` counts the truth values it cannot score.** A typo'd option or question id in a hand-written truth file used to shrink `n` without a word, which reads as a smaller sample rather than a broken file. The count is per question and printed under the tables.
- **2026-09-18 — `--dry-run` resolves provider and model the way the real call does.** The preview exists to show the wire body, and the body differs by provider (entries JSON-encoded for OpenRouter, raw for TypeSafe), so a preview pinned to OpenRouter showed the wrong body whenever `JEV_PROVIDER=typesafe`.
- **2026-09-23 — `null` is allowed only as a Choice option value.** Sent live, OpenRouter returns a 400 for a null or missing instruction, a null Score level, and a null Noul side, and accepts `null` as an option value. The API reference agrees; the advanced-structure page lists `null` everywhere. The client used to JSON-encode a null to the string `"null"`, which OpenRouter took as the question text, so the types now rule the other positions out.
